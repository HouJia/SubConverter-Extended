## 1. 和原版 subconverter 的关系

| 层次 | 说明 |
|------|------|
| **保留** | 经典 **`/sub?target=...&url=...`** 订阅转换、ruleset、外部配置、多客户端格式导出 |
| **Extended 新增** | Mihomo 配置桥接、HTML **版本页**、**诊断台**、可选 **统计面板**、更完整的 Hy2 / sing-box 字段等 |
| **HouJia 增量** | NAS 两阶段 Docker、`max_allowed_rulesets=256`、MetaCubeX `?ua=`、NPM `/subapi` 集成文档 |

**结论**：不是「只做协议转换」那么简单；**转换仍是核心**，Extended 在转换链路上加了 Mihomo 适配与运维向页面。

## 2. HTTP 路径前缀（base path）说明

有两类「路径」，不要混淆：

| 名称 | 配置位置 | 含义 |
|------|----------|------|
| **`base_path`（pref.toml）** | `[common] base_path = "base"` | 生成配置时 **规则/模板文件** 在镜像内的目录 scope，**不是** 浏览器 URL 前缀 |
| **公网 URL 前缀 `/subapi`** | **Nginx Proxy Manager** | 反代约定；容器内仍是 `/sub`、`/version`；**不能**在 `pref.toml` 一条改成 `/foo` |

HTML 页面在 NPM 子路径下的资源解析：

- `page_assets::BASE_TAG_SCRIPT`：按浏览器 `pathname` 注入 `<base href="...">`
- NPM 发送 `X-Forwarded-Prefix: /subapi`（服务端改写兜底）
- 详见 [技术迭代-NAS部署与NPM暴露.md](技术迭代-NAS部署与NPM暴露.md) §1.2

**改公网前缀**：改 NPM Custom Location 与 sub-web 的 `VITE_SUBCONVERTER_DEFAULT_BACKEND`，并同步 Extended 文档中的验收 URL。

## 3. 功能一览与访问方式

### 3.1 订阅转换 API（核心）

| 内网 | 公网（NPM） |
|------|-------------|
| `http://<NAS>:25500/sub?target=clash&url=...` | `https://<域名>/subapi/sub?target=clash&url=...` |

- **用途**：拉取订阅并转换为目标格式（clash、singbox、surge 等）。
- **前端**： [sub-web](https://github.com/HouJia/sub-web) 默认请求公网 `/subapi/sub?...`。
- **常见别名**：`/clash`、`/singbox` 等（见 `pref.toml` `[[aliases]]`）。

### 3.2 版本页 `/version`

| 内网 | 公网 |
|------|------|
| `http://<NAS>:25500/` → 302 `/version` | `https://<域名>/subapi` → 301 `/subapi/version` |
| `http://<NAS>:25500/version` | `https://<域名>/subapi/version` |

- **用途**：查看构建版本、commit、构建日期；浏览器 favicon/logo。
- **纯文本**（给 sub-web 页眉）：`/version.txt` → 公网 `/subapi/version.txt`。

### 3.3 诊断台 `/inspect`

| 内网 | 公网 |
|------|------|
| `http://<NAS>:25500/inspect` | `https://<域名>/subapi/inspect` |

- **用途**：在浏览器里 **粘贴一条转换请求**（如 `target=clash&url=...&config=...`），调用 `/sub?explain=true` 查看解析结果、节点摘要、规则命中等，**无需 curl**。
- **用法**：
  1. 打开 `/inspect`
  2. 在输入框粘贴 query（页面预填示例，可改成你的真实 `url`）
  3. 点击运行 / Inspect
  4. 查看下方结构化报告（节点数、过滤、外部配置等）
- **适合**：排查「为什么转换结果不对」「某节点被过滤」类问题。

### 3.4 统计面板 `/dashboard`

| 内网 | 公网 |
|------|------|
| `http://<NAS>:25500/dashboard` | `https://<域名>/subapi/dashboard` |

- **用途**：Extended **可选**运行时统计（转换次数、地区分布等），需 `pref.toml` 中 `[statistics] enabled = true`。
- **数据**：默认写入容器内 `stats/statistics.json`（重建容器会清空，除非挂卷）。
- **认证**：见 [§5](#5-dashboard-认证说明)。

### 3.5 其它管理端点

| 路径 | 说明 |
|------|------|
| `/healthz` | 健康检查 |
| `/flushcache` | 清缓存（视配置） |
| `/readconf` | 读配置（视权限） |
| `/getruleset` | 拉取 ruleset |

完整 API 以 `main.cpp` 注册路由为准；上表为日常运维最常见项。

## 4. favicon 路径为何分两种写法

favicon **只注册在** `GET /version/favicon-*.svg`（单一 HTTP 资源，非内联 SVG）。

| 页面 | HTML 写法 | 原因 |
|------|-----------|------|
| **`/version`** | `favicon-light.svg` | `<base href=".../version/">` 下，相对路径即 `/version/favicon-*.svg` |
| **`/inspect`、`/dashboard`** | `../version/favicon-light.svg` | `<base href=".../inspect/">` 时，若写 `favicon-light.svg` 会变成 `/inspect/favicon-*` → **404**；`../version/` 指向真实路由 |

公网 `/subapi/inspect` 同理：解析为 `/subapi/version/favicon-light.svg`。

## 6. X-Forwarded-Prefix 与 base_path（FAQ）

| 概念 | 谁定义 | 作用 |
|------|--------|------|
| **`X-Forwarded-Prefix`** | 非 IETF RFC；常见于 **Traefik**、部分反向代理与应用的约定 | **NPM → 后端**：请求头，告诉应用「用户访问的 URL 前缀是 `/subapi`」；**应用**若实现读头，可改写 HTML/API 链接。**Nginx 不据此路由** |
| **`base_path`（pref.toml）** | 本项目配置 | 规则/模板**文件**在镜像内的目录 scope，**不是**浏览器 URL 前缀 |
| **NPM `location /subapi/`** | 你的 NPM 配置 | **真正做转发**的一层：决定请求进哪个端口、剥哪段前缀 |
| **sub-web `VITE_BASE_PATH`** | 构建时 | 前端静态资源与路由的 base，与 `X-Forwarded-Prefix` 无关 |

**常见误解：**

- ❌ 浏览器每次请求带 `X-Forwarded-Prefix` → **错**；该头由 **NPM 在反代时注入**，浏览器一般看不到、也不发送。
- ❌ Nginx 读 `X-Forwarded-Prefix` 决定转发目标 → **错**；转发靠 `location` + `proxy_pass`。
- ❌ 只设头、应用不改绝对路径（如 `fetch("/dashboard/data")`）→ **仍会 404**；须相对路径 + `<base>` 或应用读头改写。

**与 dashboard 空数据的关系：** 页面在 `/subapi/dashboard`，但 JS 写死 `fetch("/dashboard/data")` 会请求站点根 `/dashboard/data`（404）。应改为相对 `dashboard/data` 或带前缀路径（已修）。

## 7. dashboard 认证说明

`pref.toml`：

```toml
[statistics]
enabled = true

[statistics.dashboard_auth]
enabled = false   # false = 打开 /dashboard 无需登录（内网体验）
username = ""
password = ""
```

| `dashboard_auth.enabled` | 行为 |
|--------------------------|------|
| **false**（HouJia NAS 默认） | 直接打开 `/dashboard`，与内网调试方便 |
| **true** | 浏览器 **HTTP Basic** 登录（官方 demo `api.asailor.org/dashboard` 即此种） |

**公网暴露时**：若 NPM 已映射 `/subapi/dashboard`，建议 `enabled = true` 并设置强密码，避免统计页对公网裸奔。
